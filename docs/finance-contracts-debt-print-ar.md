# مرجع للطباعة — العقود، المالية، الديون، وأوامر البيع

**مصدر الوثيقة:** متطلبات المشروع (rev **4.1**) — `steel-erp-requirements-en.plan.md` والنسخة العربية.  
**الغرض:** جلسة مراجعة داخلية أو أرشفة؛ ليس نصاً قانونياً نهائياً.

## 1) عقد البيع العام (المظلة السنوية)

| الموضوع | القرار المعتمد |
|--------|----------------|
| دور العقد | مظلة سنوية (هوية تعامل + مرفق عقد موقّع إلزامي). |
| الكميات والأسعار | لا تُثبت على العقد؛ التنفيذ عبر **أوامر البيع**. |
| نهاية السنة | فترة العقد مرتبطة بسنة تقويمية (انتهاء تشغيلي 31/12). |
| أمر البيع تحت العقد | أي **أمر بيع** أُنشئ تحت المظلة يبقى على **نفس العقد** حتى يصل الأمر لحالة **نهائية** (مكتمل / ملغى / إغلاق إداري) — بما في ذلك عبور نهاية السنة. |
| عقد سنة جديدة | رقم عقد جديد؛ **لا نقل تلقائي** لأوامر البيع المفتوحة إلى عقد السنة الجديدة. |
| تعليق العقد | يمنع تسجيل شاحنات **جديدة** لكل أوامر البيع تحته؛ الشاحنات قيد التنفيذ تُكمل؛ سبب إجباري في السجل. |

---

## 2) أمر البيع (Sales Order)

| الموضوع | القرار المعتمد |
|--------|----------------|
| الترقيم | `YY-CC-OOO` تحت عقد `YY-CC`. |
| نوع السلعة | سطر عمل واحد لكل أمر (مبروم / Shortbar نطاق / Scrap). |
| نمط التسوية (عند الإنشاء) | **آجل `CREDIT`** أو **نظام دفعات `PAYMENT_PLAN`**. |
| آجل | شرائح يوم تقويمي؛ مهلة كل شريحة = تاريخ الإثبات + **`payment_deadline_days`** (يُحدد لكل أمر — ليس رقماً عالمياً ثابتاً). |
| نظام الدفعات | دفعة ثم تحميل بالقيمة؛ عادة لا تحميل لاحق بدون تغطية؛ **استثناء إداري** مسجّل للتحميل دون دفع. |
| السماحية والكمية | سقف `max_allowed`؛ تجاوزه يتطلب موافقة مالية/إدارة + سبب في سجل التدقيق. |
| الأسعار (v1) | بعد **اعتماد أمر البيع**، الأسعار **ثابتة لذلك الأمر** لكل التحميلات حتى يُبنى لاحقاً مسار «تعديل سعر». |

---

## 3) الدين والأرصدة

| الموضوع | القرار المعتمد |
|--------|----------------|
| مرجع الدين التشغيلي | **لكل أمر بيع**: قيمة المحمّل − ما طُبّق من دفعات على ذلك الأمر (مع FIFO على مستوى العميل). |
| سقف دين رقمي ثابت | **غير معتمد في v1** — لا رقم مخزّن على العميل أو العقد كحد أعلى للدين. |
| نطاق التفويض الآجل | **عميل + أمر بيع**: صلاحية التعامل بالآجل تُستمد من **اعتماد أمر البيع الآجل** (النمط، الأسعار، المهل، السماحية). |
| FIFO | الدفعات تُطبَّق على **أقدم أمر بيع غير مسدد** — إجبار نظامي. |
| دفعة زائدة | رصيد دائن للعميل؛ تخصيص يدوي لاحقاً. |
| التمرير الإجباري | لا يلغي الدين؛ العجز يبقى مسجّلاً. |

---

## 4) الفحص المسبق قبل التحميل (ملخص)

| نمط الأمر | الفكرة |
|-----------|--------|
| **CREDIT** | لا مقارنة بسقف رقمي؛ التحقق على **أمر البيع الحالي** و**انضباط الشرائح** و`payment_deadline_days`؛ التأخر على شريحة = **تحذير** في الوثيقة الحالية (منع لاحقاً اختياري). |
| **PAYMENT_PLAN** | تغطية مالية للتحميل المقدَّر **أو** استثناء «تحميل دون دفع» مسجّل. |
| مشترك | فلتر النسبة الخاصة (8+10) إن انطبق؛ فلتر سماحية الكمية الإجمالية. |

---

## 5) التقارير (المستويان المطلوبان)

| المستوى | الغرض |
|---------|--------|
| **أمر بيع** | متابعة التزام كل طلبية (كمية، رصيد، شرائح). |
| **عميل** | تجميع إجمالي التعرّض / الديون من **جميع أوامر البيع المفتوحة**. |

## 6) نقاط ناقصة أو ضبابية (للمتابعة)

استخدم العمود الأيمن في الطباعة لوضع علامة (✓) أو ملاحظة اجتماع المالية.

| # | الموضوع | ملاحظة |
|---|---------|--------|
| A | **تعديل السعر بعد اعتماد أمر البيع** | غير موجود في v1؛ يحتاج تصميم لاحق (إصدارات، تاريخ نفاذ، شاحنات قيد التنفيذ). |
| B | **منع التحميل عند تأخر شرائح الآجل** | الوثيقة: حالياً **تحذير** فقط؛ هل تريدون لاحقاً **منعاً** عند تجاوز المهلة؟ |
| C | **وثائق مطبوعة** | فاتورة؟ كشف حساب؟ — غير محدد في المتطلبات. |
| D | **تفاصيل الدفعات** | بعض التفاصيل ما زالت «قيد الصقل» في الوثيقة الإنجليزية؛ تأكيد نماذج الإدخال الميدانية مع المالية. |
| E | **مشتريات / مخزون** | خارج نطاق البيع الحالي؛ غير محسوم التكامل. |
| F | **صلاحية `creditlimit.set`** | محجوزة في الوثيقة و**غير مستخدمة في v1**؛ إما حذف لاحقاً أو إعادة تعريف إذا طُلب سقف مستقبلاً. |
| G | **حقل `credit_limit` في مخطط أمر البيع (ERD)** | معلّم كإرث؛ تجاهله في التنفيذ أو إزالته من المخطط عند التنظيف. |
