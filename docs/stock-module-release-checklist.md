# خطة تفعيل موديول المخزون على الإنتاج

> الموديول منشور بالكود لكنه مخفي (Dark Launch) خلف متغيّر البيئة
> `STOCK_MODULE_ENABLED`. هذا الملف هو قائمة الخطوات الكاملة لتفعيله لاحقاً.
>
> **فكرة التسلسل**: لا يوجد أي دور لديه صلاحيات مخزون افتراضياً، لذلك تفعيل
> الفلاغ وحده يُظهر الموديول **للأدمن فقط** (يرث كل الصلاحيات). هذا يعطينا
> مرحلة تجهيز آمنة: نفعّل، الأدمن يجهّز الساحات والأرصدة، وبعدها فقط نمنح
> الصلاحيات للموظفين.

---

## المرحلة 0 — فحوصات ما قبل أي شيء (على السيرفر)

- [ ] `pwd` = `/opt/steel-erp/app`، الفرع `main`، و`git status` نظيف.
- [ ] `df -h /` ≥ 15% حرة، و`free -h` تُظهر MemAvailable ≥ 300 MB.
- [ ] `pm2 status` يُظهر `steel-erp` بحالة `online`.
- [ ] آخر نشر تم عبر `deploy.sh` ونجح فحص الصحة
      (`curl -sf http://localhost:3000/api/health` يرجع 200 مع `dbConnected: true`).
- [ ] التأكد أن migrations المخزون الثلاثة مطبّقة:
      `npx prisma migrate status` (يجب أن تظهر `20260712120000_add_stock_module`
      و`20260713110500_add_stock_movement_shift`
      و`20260713113000_add_crossdock_virtual_location` كمطبّقة).

## المرحلة 1 — قلب المفتاح (يظهر للأدمن فقط)

- [ ] أضف إلى `/opt/steel-erp/app/.env.production`:

  ```
  STOCK_MODULE_ENABLED=true
  ```

- [ ] `pm2 reload steel-erp`
- [ ] تحقق: فحص الصحة يرجع 200، والدخول كأدمن يُظهر قسم «المخزون» بالقائمة.
- [ ] تحقق: مستخدم عادي (غير أدمن) **لا** يرى القسم ولا يستطيع فتح `/stock`.
- [ ] سجّل الإجراء في `/opt/steel-erp/CHANGES.md` (تغيير env = إجراء مُغيِّر).

## المرحلة 2 — تجهيز الساحات والمواقع (أدمن فقط)

- [ ] من واجهة `/stock/locations`: أنشئ الساحات (أمامية/خلفية) والمواقع حسب
      خريطة الساحة الفعلية (القطاعات: عام / محافظات / عزل / قصائر).
      **ملاحظة**: seed لا يعمل على الإنتاج إطلاقاً — الإنشاء يدوي من الواجهة.

## المرحلة 3 — إنشاء الموقع الافتراضي `__DIRECT__` (خطوة إلزامية!)

> ⚠️ **لماذا؟** الـ migration التي تزرع هذا الموقع نفّذت `INSERT ... SELECT`
> من `stock_yards` وكان الجدول **فارغاً** وقتها على الإنتاج، فلم يُزرع شيء،
> والـ migration لا تعيد التشغيل. بدون هذا الموقع، أي وزنة «من خط الإنتاج
> مباشرة» ستُفشل **إغلاق الشاحنة** برسالة
> «الموقع الافتراضي للتسليم المباشر غير موجود».

- [ ] بعد إنشاء الساحات (المرحلة 2)، نفّذ على السيرفر:

  ```bash
  sudo -u postgres psql -d steel_erp_prod -c "
  INSERT INTO stock_locations
    (yard_id, code, name_ar, segment, unit, allowed_grade,
     is_active, is_virtual, sort_order, grid_row, grid_col, grid_span,
     created_at, updated_at)
  SELECT y.id, '__DIRECT__', 'خط الإنتاج (تسليم مباشر)', 'GENERAL', 'BUNDLE', NULL,
         true, true, 9999, 1, 1, 1, now(), now()
  FROM stock_yards y
  ORDER BY y.id ASC
  LIMIT 1
  ON CONFLICT DO NOTHING;"
  ```

- [ ] تحقق أنه أُنشئ:

  ```bash
  sudo -u postgres psql -d steel_erp_prod -c \
    "SELECT id, code, is_virtual FROM stock_locations WHERE is_virtual = true;"
  ```

  يجب أن يظهر صف واحد بالضبط بكود `__DIRECT__`.

- [ ] سجّل الإجراء في `CHANGES.md`.

## المرحلة 4 — الأرصدة الافتتاحية (أدمن)

- [ ] أدخل الأرصدة الحالية الفعلية لكل موقع عبر «تصحيح الجرد» (`/stock/adjust`)
      بعد جرد فعلي للساحة (ربطات للمبروم + طن، وطن فقط للقصائر).
- [ ] راجع الخريطة (`/stock`) وتأكد أن الأرقام تطابق الواقع.

## المرحلة 5 — منح الصلاحيات للموظفين (الإطلاق الفعلي)

- [ ] في `prisma/rbac-source.ts` أعد `stock.view` إلى افتراضيات الأدوار
      (المواضع معلّمة بتعليقات «dark-launched» داخل الملف):
  - `logistics` — يرى الخريطة والأرصدة.
  - `internal_loader` — يحتاجها لاختيار موقع المصدر في نافذة الوزنة.
  - `manager` — عرض فقط.
- [ ] قرّر إسناد بقية الصلاحيات (افتراضيات أدوار أو منح فردية من واجهة الأدمن):
  - `stock.production.ton` / `stock.production.bundle` — موظفَا تسجيل الإنتاج
    (تكفي وحدها لفتح `/stock/production-in`؛ لا يشترطان `stock.view`).
  - `stock.transfer` — من ينفّذ الترحيل بين المواقع.
  - `stock.adjust` — من يصحّح الجرد.
  - `stock.movements.view` — من يدقّق سجل الحركات (ليست افتراضية لأي دور — منح فردي).
  - `stock.location.manage` — إدارة المواقع (يُفضَّل إبقاؤها للأدمن).
  - `stock.view` — فقط لمن يحتاج خريطة الأرصدة `/stock` (مدير، لوجستيك، محمّل…).
- [ ] انشر التعديل (commit + deploy عبر `deploy.sh`) ثم:

  ```bash
  npm run rbac:sync:dry   # راجع الناتج أولاً
  npm run rbac:sync
  ```

- [ ] سجّل الإجراء في `CHANGES.md`.

## المرحلة 6 — تحقق نهائي

- [ ] بمستخدم `internal_loader`: نافذة الوزنة تعرض حقل «المصدر» مع المواقع
      وخيار «من خط الإنتاج مباشرة».
- [ ] عملية شاحنة تجريبية واحدة من البداية للنهاية: وزنة من موقع حقيقي →
      إغلاق → التأكد أن الرصيد نقص في `/stock` وظهر `LOAD_OUT` في سجل الحركات.
- [ ] وزنة «من خط الإنتاج مباشرة» → إغلاق → التأكد أن السجل يُظهر
      استلاماً وخروجاً متقابلين على الموقع الافتراضي (صافي صفر) وأن الإغلاق نجح.
- [ ] بموظف تسجيل إنتاج: إدخال إنتاج (طن/ربطات حسب صلاحيته) ورؤية
      «إدخالات اليوم» مقسّمة بالورديات.

## التراجع (Rollback)

أي مشكلة → إخفاء فوري للموديول كاملاً دون المساس بالبيانات:

```bash
# في .env.production: احذف السطر أو اجعله STOCK_MODULE_ENABLED=false
pm2 reload steel-erp
```

- الحركات المسجّلة تبقى محفوظة بقاعدة البيانات (لا تُحذف ولا تتأثر).
- خصم المخزون عند إغلاق الشاحنات يتوقف فوراً (الإغلاق نفسه يعمل طبيعياً).
- صلاحيات الأدوار الممنوحة في المرحلة 5 لا تحتاج تراجعاً — الفلاغ يحجب الجميع.
- سجّل التراجع في `CHANGES.md`.

---

## تذكيرات

- الفلاغ يُقرأ وقت التشغيل (ليس وقت الـ build) — قلبه يحتاج `pm2 reload` فقط،
  **بدون إعادة بناء**.
- محلياً: `STOCK_MODULE_ENABLED=true` موجود في `.env` (غير مرفوع على git) —
  لا تلمسه؛ التطوير المحلي يرى الموديول دائماً.
- لا تشغّل seed أو أي سكربت reset على الإنتاج إطلاقاً (قواعد الإنتاج §7).
